### Мотивация

| Проблема | Цель мониторинга |
|-|-|
| Рост жалоб клиентов | Выявление bottle-neck в системе |
| Просроченные заказы | Контроль времени обработки заказов. Также не факт, что эти заказы вообще не исчезают в процессе обработки |
| Медленная загрузка MES | Диагностика производительности |
| Потеря крупных контрактов | Превентивное обнаружение проблем |

### Выбор подхода к мониторингу

| Подсистема | Выбранный подход | Обоснование |
|-|-|-|
| API-сервисы | RED | Высокая нагрузка, необходим контроль запросов |
| Базы данных | USE | Критичность ресурсов для производительности |
| Очередь сообщений | Четыре золотых сигнала | Важность надежной коммуникации между сервисами |

| Метрика | Зачем нужна | Ярлыки |
|-|-|-|
| Number of requests (RPS) for MES API | Оценка нагрузки на сервис расчета стоимости | - service: mes-api<br>- type: performance |
| Response time (latency) for MES API | Контроль времени обработки сложных 3D-моделей | - service: mes-api<br>- type: performance |
| Number of HTTP 500 for MES API | Выявление критических ошибок | - service: mes-api<br>- type: error<br>- severity: high |
| Number of dead-letter-exchange letters in RabbitMQ | Диагностика проблем в очереди сообщений | - service: message-queue<br>- type: reliability |
| Memory Utilisation for MES API | Контроль потребления памяти при расчетах | - service: mes-api<br>- type: resource |
| Number of simultaneous sessions for MES API | Понимание параллельной нагрузки | - service: mes-api<br>- type: concurrency |

Дополнительные метрики

| Метрика | Зачем нужна | Ярлыки |
|-|-|-|
| Order Processing Time | Время от создания до завершения заказа | - domain: order-management<br>- type: business-metric |
| 3D Model service-a Duration | Время расчета стоимости изделия | - domain: pricing<br>- type: performance |
| API Response Success Rate | Доля успешных запросов | - type: reliability<br>- scope: api-performance |

План действий

1. Анализ производительности и узких мест
- Провести профилирование всех компонентов системы (MES, CRM, онлайн-магазин)
- Выявить bottleneck'и в текущей архитектуре
- Составить детальный отчет о текущей производительности каждого сервиса

2. Оптимизация базы данных
- Создать инстанс time-series базы данных (например, InfluxDB) для хранения метрик производства и статусов заказов
- Реализовать партиционирование в существующих базах данных
- Добавить кэширование часто запрашиваемых данных с использованием Redis

3. Масштабирование инфраструктуры
- Внедрить горизонтальное масштабирование для MES и CRM
- Настроить балансировку нагрузки между инстансами
- Реализовать автоматическое горизонтальное масштабирование с использованием Kubernetes

4. Оптимизация очередей и коммуникации между сервисами
- Провести аудит текущей реализации RabbitMQ
- Внедрить систему circuit breaker для обработки ошибок между сервисами
- Добавить мониторинг производительности очередей сообщений

5. Улучшение процессов разработки
- Внедрить автоматизированное E2E-тестирование
- Настроить систему непрерывной интеграции с более быстрым циклом релизов
- Реализовать систему мониторинга и алертинга (например, Prometheus + Grafana)

6. Оптимизация работы с заказами
- Разработать механизм приоритезации заказов
- Создать систему прогнозирования сроков выполнения заказов
- Внедрить детальную аналитику простоев и задержек в производственном цикле

7. Улучшение API и интеграций
- Разработать версионность API
- Внедрить механизмы throttling и rate limiting
- Создать детальную документацию по API с использованием Swagger

8. Оптимизация производительности фронтенда
- Реализовать lazy loading для страниц MES
- Внедрить эффективную пагинацию и виртуализацию списков
- Оптимизировать серверный рендеринг для улучшения первоначальной загрузки

Ожидаемые результаты:
- Сокращение времени обработки заказов на 50%
- Уменьшение количества жалоб клиентов на 70%
- Повышение отказоустойчивости системы
- Улучшение масштабируемости инфраструктуры
