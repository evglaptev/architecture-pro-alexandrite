## Анализ проблемных мест системы

| № | Категория | Проблема | Последствия |
|-|-|-|-|
| 1 | Производительность | Долгий расчет стоимости изделия (до 30 минут) | Снижение удовлетворенности клиентов, потеря заказов |
| 2 | Масштабирование | Линейный рост нагрузки без горизонтального масштабирования | Деградация производительности при увеличении числа заказов |
| 3 | Интеграция | Сложная межсистемная коммуникация через RabbitMQ | Возможные потери сообщений, задержки в обработке |
| 4 | Мониторинг | Отсутствие явных механизмов отслеживания просроченных заказов | Рост числа жалоб, потеря репутации |
| 5 | Архитектура | Разные технологические стеки для компонентов (Vue, React, Java, C#) | Сложность поддержки, интеграции и обмена опытом |
| 6 | Инфраструктура | Один инстанс баз данных для чтения и записи | Риски производительности и отказоустойчивости |
| 7 | Процессы | Ручной деплой в релиз и продакшн | Замедление выпуска обновлений |
| 8 | Тестирование | Ручное E2E-тестирование с блокировкой релизов | Длительные задержки выпуска версий |
| 9 | Бизнес-процесс | Отсутствие четкого SLA для обработки заказов | Рост числа жалоб, потеря клиентов |
| 10 | UI/UX | Медленная загрузка дашборда в MES | Снижение эффективности работы операторов, жалобы на долгий отклик |
| 11 | Распределенная система | Отсутствие централизованного логирования и трейсинга | Сложность диагностики проблем |
| 12 | Безопасность | Открытие API без явных механизмов throttling | Риски DDoS, неконтролируемой нагрузки |

## Инициативы по улучшению

В порядке приоритета:

1. Система мониторинга и логирования:
- Логирование
- Метрики, создание дашбордов с алёртами
- Трейсинг

2. Оптимизация производительности MES: 
- Кэширование расчетов стоимости
- Оптимизация алгоритмов расчета
- Горизонтальное масштабирование MES API


3. Автоматизация тестирования

4. Архитектурная трансформация
- Требуется введение микросервисной архитектуры
- Если клиенты жалуются на выполнение заказов, а причины их невыполнения похоже упираются в bottle-neck системы - MES API, то необходимо
  представить Event-Driven архитектуру, чтобы заказ гарантировано выполнился спустя какое-то время, но никак не был утерян.

Целевая архитектура через 6 месяцев:

- Микросервисная архитектура
- Горизонтально масштабируемые сервисы
- Централизованное отслеживание заказов
- Автоматизированный CI/CD
- Распределенное кэширование
- Event sourcing для статусов заказов
